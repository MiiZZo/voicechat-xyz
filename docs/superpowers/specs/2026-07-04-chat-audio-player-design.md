# Встроенный аудиоплеер в чате

**Дата:** 2026-07-04
**Область:** UI (общий рендерер `apps/client/src/renderer/`)

## Цель

Дать возможность проигрывать загруженные в чат аудиофайлы прямо в интерфейсе,
не скачивая их. Сейчас любой файл, кроме изображений, показывается как
«файловый пузырёк» с единственной кнопкой «скачать» (`ChatPanel.tsx`,
компонент `FileBubble`).

## Границы

- **В области:** компактный inline-плеер для файловых сообщений, которые
  являются аудио.
- **Вне области:** запись голосовых сообщений, вещание звука всем участникам
  звонка через LiveKit, waveform-визуализация, изменения сервера/загрузки/
  нативных команд.

Фича живёт целиком в общем рендерере, поэтому автоматически работает в обоих
клиентах (Electron и Tauri) без правок нативного слоя.

## Определение «это аудио»

Файловое сообщение считается аудио, если:

```
message.mime.startsWith('audio/')
  || AUDIO_EXT_RE.test(message.name)
```

где `AUDIO_EXT_RE` покрывает расширения: `mp3, ogg, oga, wav, m4a, aac,
flac, opus, webm`. Расширение нужно как запасной вариант, т.к. при загрузке
mime иногда приходит `application/octet-stream`.

Плеер показывается только когда `status === 'done'` и есть непустой `url`.
Во время загрузки (`status: 'uploading'`) и при ошибке (`status: 'error'`)
поведение не меняется — остаётся текущий файловый пузырёк.

## Компонент `AudioBubble`

Новый файл `apps/client/src/renderer/components/AudioBubble.tsx`.
`FileBubble` внутри `ChatPanel.tsx` роутит на него по признаку «это аудио»
(так же, как сейчас роутит на inline-картинку). Отдельный файл — чтобы не
раздувать уже большой `ChatPanel.tsx` и держать плеер как самостоятельный,
тестируемый юнит.

**Пропсы:** `{ message: FileMessage; isLocal: boolean; onDownload: () => void | Promise<void> }`.
`onDownload` приходит из `FileBubble`, который уже владеет логикой скачивания
через `window.api.downloadFile` — не дублируем её.

**Разметка:**
- Скрытый `<audio ref preload="metadata" src={message.url}>`.
- Круглая кнопка **play/pause** слева (иконки `Play`/`Pause` из lucide-react).
- **Полоса прогресса** — кликабельный трек (seek): по клику
  `audio.currentTime = fraction * duration`. Тонкая, нейтральный зинк
  заполнения, в духе Velvet Onyx.
- **Время** `mm:ss / mm:ss` моноширинным шрифтом. Если `duration` не число
  или `Infinity` — показываем `--:--`.
- **Имя файла** сверху, `truncate`.
- **Кнопка скачать** справа — тот же вид, что у `FileBubble`.

**Состояние:** локальный `useState` — `playing`, `currentTime`, `duration`.
Синхронизация через события `<audio>`: `loadedmetadata`, `timeupdate`,
`play`, `pause`, `ended`. При размонтировании слушатели снимаются.

**Стиль local/remote:** те же классы контейнера, что у `FileBubble`
(жемчужный градиент для своих сообщений, стеклянный для чужих).

## Осознанно не делаем (YAGNI)

- Нет waveform.
- Нет глобальной координации «играет только один трек» — каждый плеер
  независим (нативное поведение `<audio>`). При необходимости добавим позже.
- Нет правок загрузки, сервера, нативных команд.

## Проверка

1. Запустить клиент, зайти в комнату.
2. Загрузить в чат `.mp3` и `.ogg`.
3. Убедиться: плеер отрисован, play/pause работает, полоса двигается при
   проигрывании и перематывает по клику, время корректное, кнопка скачать
   работает.
4. Регресс: изображения по-прежнему показываются с превью/лайтбоксом,
   обычные файлы (`.pdf`, `.zip`) — как файловый пузырёк со скачиванием;
   индикатор загрузки и состояние ошибки не изменились.
5. `npm run` typecheck/lint проходит.
